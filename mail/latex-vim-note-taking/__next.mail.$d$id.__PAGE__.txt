<h2>摘要</h2>
<p>Gilles Castel 介绍了自己如何用 Vim、LaTeX 和 UltiSnips 在数学课上实时记笔记。核心方法不是单纯提高打字速度，而是把高频 LaTeX 结构做成可自动展开的 snippets，让公式、环境、分数、上下标、向量符号、拼写修正都能快速完成，从而把 LaTeX 变成接近手写速度的课堂记录工具。</p>
<h2>内容框架与概述</h2>
<p>作者从自己的课堂笔记实践说起。他从数学本科第二学期开始使用 LaTeX 记课，到写作时已经积累了超过 1700 页笔记。这些笔记包括公式和图形，都是在听课过程中同步完成，之后没有再编辑。为了让 LaTeX 课堂笔记可行，他设定了几个目标：公式输入要跟得上老师板书，图形绘制也要足够快，笔记管理要方便，还要能在 PDF 旁边做 LaTeX 注释。</p>
<p>文章重点放在第一个目标，也就是如何快速写 LaTeX。作者使用 Vim 作为主要编辑器，配合 vimtex 插件完成语法高亮、目录视图、同步定位和 PDF 预览。右侧用 Zathura 查看编译后的 PDF。Vim 的 conceal 功能会把部分 LaTeX 代码隐藏或替换成更接近数学符号的形式，比如把 \in 显示成 ∈，这样编辑时页面更接近最终排版效果，干扰更少。</p>
<p>真正提高速度的关键是 UltiSnips。作者把大量高频输入变成 snippets，比如 beg 自动生成 begin 和 end 环境，mk 和 dm 分别进入行内公式和展示公式，a1 自动变成 a_1，sr 自动变成平方，上标、分数、向量、极限、求和、集合符号都能通过短触发词完成。更复杂的 snippets 还会使用正则表达式、Python、Sympy 或 Mathematica 来处理数学表达式。为了避免普通英文单词误触发数学 snippets，作者还用 vimtex 判断当前是否处在数学环境中。</p>
<h2>核心概念及解读</h2>
<h3>Snippet，代码片段</h3>
<p>Snippet 是一种文本自动展开机制。你输入一个很短的触发词，再按下快捷键，编辑器就把它扩展成完整结构。比如输入 beg 可以生成 LaTeX 环境，输入 mk 可以生成行内公式。它的价值在于把重复操作变成肌肉记忆，减少打字量，也减少语法错误。</p>
<h3>UltiSnips，Vim 片段引擎</h3>
<p>UltiSnips 是 Vim 中管理 snippets 的插件。它支持普通文本替换，也支持动态代码执行，比如用 Bash 插入当天日期，用 Python 根据输入内容生成盒子、分数或复杂结构。对数学笔记来说，它相当于一个轻量级自动化层，把 LaTeX 的繁琐语法压缩成短命令。</p>
<h3>Math mode，数学模式</h3>
<p>LaTeX 中公式需要进入数学模式，常见形式包括行内公式和展示公式。作者用 mk 和 dm 两个 snippets 快速切换。这样做的好处是，写公式时不用手动敲成对的美元符号或方括号，也不容易忘记闭合符号和句末标点。</p>
<h3>Context，上下文判断</h3>
<p>很多 snippets 只应该在公式里展开。例如 sr 在数学环境中代表平方，但在普通英文单词 disregard 中也会出现 sr。为了解决冲突，作者借助 vimtex 判断当前光标是否处在数学区域，只在合适环境中展开对应 snippets。这一步很重要，否则自动化会反过来制造麻烦。</p>
<h3>Postfix snippet，后缀片段</h3>
<p>后缀片段是把操作放在变量后面写，比如 phat 变成 \hat{p}，zbar 变成 \overline{z}，v,. 变成 \vec{v}。它符合课堂板书的顺序：老师先写变量，再加帽子、横线或箭头。输入顺序和视觉顺序一致，速度自然会更快。</p>

<h2>用 LaTeX 记数学课堂笔记，关键不是手速，而是输入系统</h2>
<p>数学课堂笔记的难点不只是把字打出来，而是要在老师板书还没擦掉之前，把文字、公式、环境、符号、图形和逻辑结构同步记录下来。普通 LaTeX 输入太慢，因为大量时间浪费在括号、反斜杠、环境闭合、上下标、分数结构这些细节上。</p>
<p>解决办法是把 LaTeX 变成一套高速输入系统。核心工具是 Vim、vimtex、UltiSnips 和大量自定义 snippets。真正的目标是减少手工输入，把常见结构变成短触发词，让公式输入接近板书速度。</p>
<h2>课堂笔记的四个目标</h2>
<h3>公式输入必须跟上黑板速度</h3>
<p>数学课上最致命的问题是延迟。一旦公式输入慢几拍，后面的推导就会断掉。LaTeX 原本适合排版，但不适合实时记录，因为语法太繁琐。</p>
<p>所以整个工作流的第一目标是：文字和数学公式输入不能拖慢听课节奏。所有重复性的 LaTeX 结构都需要自动化，尽量让输入动作短、稳定、可预期。</p>
<h3>图形绘制也要接近课堂速度</h3>
<p>数学笔记不只有公式，还有图形、示意图、交换图、坐标轴、集合关系。图形如果课后补，容易丢失课堂上下文。作者的整个系统还包括 Inkscape 画图，不过当前内容主要集中在文字和公式输入。</p>
<p>图形部分虽然不是重点，但它说明了一个完整的数学笔记系统不能只解决公式。公式、图形、编译、预览、管理都要连成一套流程。</p>
<h3>笔记管理要快速</h3>
<p>课堂笔记不是孤立文件，而是一套长期积累的资料。新增笔记、编译全部笔记、只编译最近几节课、搜索旧内容，这些动作都要快。</p>
<p>如果管理成本太高，LaTeX 的优势会被抵消。真正可持续的系统，必须让文件组织、编译和检索都省事。</p>
<h3>PDF 注释也要能接入 LaTeX</h3>
<p>很多课程会给讲义或论文，学生需要在 PDF 旁边补充公式和解释。这个需求意味着笔记系统不能只服务于从零写文档，还要支持已有材料上的补充记录。</p>
<p>这也体现出作者的目标不是炫技，而是把数学学习中的几个常见场景都纳入同一套工具链。</p>
<h2>Vim 是整个输入系统的底座</h2>
<h3>Vim 适合高频文本操作</h3>
<p>Vim 的价值在于它是高度可扩展的文本编辑器。写代码、写 LaTeX、写 Markdown，本质上都是处理文本。熟悉 Vim 后，很多编辑动作可以通过键盘完成，不需要频繁离开输入区。</p>
<p>这对课堂笔记很重要。因为实时记笔记时，每一次鼠标操作、每一次手动补括号、每一次调整光标，都会打断节奏。</p>
<h3>vimtex 提供 LaTeX 编辑能力</h3>
<p>vimtex 负责补齐 Vim 在 LaTeX 场景下的能力，比如语法高亮、目录视图、同步定位、编译反馈和 PDF 预览配合。作者用 Zathura 作为 PDF 查看器，因为它也有 Vim 风格的键位。</p>
<p>左边写 LaTeX，右边看编译结果，这让输入和反馈在同一个屏幕内完成。输入错误、排版问题、公式结构是否正确，都能快速看到。</p>
<h3>conceal 让源码更接近数学表达</h3>
<p>LaTeX 源码里充满反斜杠和控制符，长期看会很干扰。conceal 功能可以把部分 LaTeX 命令隐藏或替换成对应数学符号，例如把 \in 显示成 ∈，把 \bigcap 显示成 ∩。</p>
<p>这样做不是为了美观，而是减少认知负担。编辑区更接近最终数学表达，眼睛不必在源码和数学含义之间来回转换。</p>
<h2>Snippet 是提速的核心</h2>
<h3>Snippet 把重复结构压缩成短触发词</h3>
<p>snippet 可以理解为一个输入替换器。输入短词，按下触发键，就展开成完整结构。比如输入 sign 展开成签名，输入 today 展开成日期，输入 box 生成一个根据内容自动变长的文本框。</p>
<p>在 LaTeX 中，这种机制的价值更大。因为 LaTeX 的高频结构非常多，而且很多结构都成对出现，例如公式环境、begin 和 end、分数的分子分母、括号、上下标。</p>
<h3>动态 snippet 可以执行代码</h3>
<p>普通 snippet 只是文本替换，动态 snippet 可以执行 Bash 或 Python。比如日期可以通过命令生成，盒子边框可以根据输入内容长度自动计算。</p>
<p>这说明 snippet 不只是快捷短语，而是一种小型程序。它可以读取用户当前输入、匹配正则、处理字符串，再生成 LaTeX 代码。</p>
<h3>snippet 可以嵌套使用</h3>
<p>一个 snippet 展开后，还可以在内部继续使用另一个 snippet。比如先生成日期，再把日期放入盒子。这种组合能力让简单片段可以搭出复杂结构。</p>
<p>这也是作者能够建立个人输入系统的关键：不是依赖一个庞大插件，而是积累大量小工具，再让它们互相配合。</p>
<h2>LaTeX 环境输入的自动化</h2>
<h3>beg 自动生成 begin 和 end</h3>
<p>LaTeX 环境最常见的结构是：</p>
<p>\begin{...}</p>
<p>\end{...}</p>
<p>手动输入不仅慢，还容易忘记闭合。作者用 beg 触发环境模板，输入环境名后，end 部分会自动同步。按 Tab 后，光标直接进入环境内部。</p>
<p>这节省的是很小的动作，但数学课上这种动作会重复几十上百次。高频动作越小，越值得自动化。</p>
<h3>自动展开减少额外按键</h3>
<p>beg 设置为行首触发，并且自动展开，不需要再按 Tab。这类设计很讲究，因为某些片段适合自动展开，某些片段必须手动触发，否则容易误伤正常文本。</p>
<p>一个好用的输入系统，关键不只是能展开，还要在正确场景展开。</p>
<h2>数学模式输入的自动化</h2>
<h3>mk 用于行内公式</h3>
<p>行内公式经常出现在普通句子中，例如定义一个变量、说明一个条件、插入一个短表达式。作者用 mk 快速生成行内数学模式。</p>
<p>更细的一点是，mk 会判断公式后面是否需要空格。如果后面接普通单词，就自动加空格；如果后面接逗号、句号、连字符，就不加空格。这种细节让输入结果更自然，也减少后续修改。</p>
<h3>dm 用于展示公式</h3>
<p>展示公式用于较长或较重要的公式。dm 会生成独立数学环境，并且默认把句号放在公式末尾，避免漏掉数学写作中的标点。</p>
<p>这体现出作者的 snippets 不只是生成 LaTeX 代码，还顺手维护写作习惯。自动化不只服务速度，也服务格式一致性。</p>
<h2>上下标输入的自动化</h2>
<h3>数字下标自动转换</h3>
<p>数学里 a1、a2、x12 这类下标非常常见。作者用正则触发规则，把 a1 自动变成 a_1，把 a_12 变成 a_{12}。</p>
<p>这个规则非常省时间，因为单字符变量加数字下标是课堂板书中的高频形式。输入时可以按自然顺序打出 a1，不需要手动切换到 LaTeX 语法。</p>
<h3>常见上标使用专门触发词</h3>
<p>平方、立方、补集这些高频上标分别有短触发词，比如 sr 生成 ^2，cb 生成 ^3，compl 生成补集上标。一般上标则用 td 生成 ^{}。</p>
<p>这里的原则是：越常见的结构，触发词越短；越泛用的结构，可以稍微长一点。这样输入效率和误触风险之间能保持平衡。</p>
<h2>分数输入是最有代表性的复杂自动化</h2>
<h3>简单分数直接展开</h3>
<p>输入 // 可以生成 \frac{}{}。这是最基础的分数模板，适合分子分母都还没写的情况。</p>
<p>这种模板虽然简单，但已经能避免反复输入 \frac 和两组花括号。</p>
<h3>已输入内容可以自动变成分子</h3>
<p>更强的地方在于，输入 3/ 可以变成 \frac{3}{}，输入 4\pi^2/ 可以变成 \frac{4\pi^2}{}。也就是说，用户先按自然顺序输入分子，再用一个斜杠把它包成分数。</p>
<p>这比先输入 \frac 再回头填分子更接近手写顺序。老师在黑板上也是先写表达式，再画分数线，输入系统顺着这个动作设计，速度会更稳。</p>
<h3>括号内容也能被识别成分子</h3>
<p>对于 (1 + 2 + 3)/ 这种情况，snippet 会识别匹配括号，把括号内部整体变成分子。更复杂的嵌套括号，则通过 Python 去寻找对应括号位置。</p>
<p>这里已经超出普通文本替换，变成了小型语法处理。它说明高效 LaTeX 输入不是靠死记命令，而是靠把常见编辑意图程序化。</p>
<h3>选中文本也可以生成分数</h3>
<p>如果已经写好一段内容，可以选中它，再触发分数 snippet，把选中内容放进分子。这个设计适合课堂上临时调整结构。</p>
<p>这类功能让输入过程有回旋空间，不必一开始就完美判断结构。</p>
<h2>Sympy 和 Mathematica 接入输入流程</h2>
<h3>Sympy 用于快速计算和转 LaTeX</h3>
<p>作者还做了一个 Sympy snippet。输入一段表达式后，可以让 Sympy 求值或转换为 LaTeX 形式。例如简单表达式可以直接得到结果。</p>
<p>这类功能使用频率不一定高，但在某些场景很有用。它把符号计算软件接进了笔记系统，减少从外部工具复制结果的步骤。</p>
<h3>Mathematica 也能作为后端</h3>
<p>类似地，Mathematica 可以通过 wolframscript 执行表达式，再返回 TeXForm。这样复杂计算可以从 Mathematica 生成 LaTeX。</p>
<p>这个思路很清楚：编辑器不只是打字工具，也可以成为各种工具的入口。只要能从命令行调用，就可以纳入笔记流程。</p>
<h2>后缀 snippet 让输入顺序贴近板书顺序</h2>
<h3>变量先写，修饰后加</h3>
<p>后缀 snippet 的典型例子是 phat 变成 \hat{p}，zbar 变成 \overline{z}，v,. 变成 \vec{v}。</p>
<p>这类设计的优势在于输入顺序自然。你先看到变量，再决定给它加帽子、横线或向量箭头。这个顺序和老师板书、学生思考的顺序一致。</p>
<h3>同时保留前缀写法</h3>
<p>作者也保留了 bar 和 hat 这样的前缀片段，只是优先级较低。这样在不同输入场景下都有选择。</p>
<p>好的工具系统不会只允许一种写法，而是让高频路径最短，同时保留备用路径。</p>
<h2>常用数学符号的短命令</h2>
<h3>高频符号被压缩成短输入</h3>
<p>除了复杂结构，作者还有约一百个常用 snippets。比如箭头、映射、集合包含、无穷大、极限、求和等，都有短触发词。</p>
<p>例如 fun 可以生成函数形式，lim 可以生成趋于无穷的极限，sum 可以生成常见求和结构，ooo 可以生成无穷大。</p>
<h3>这些短命令本质上是个人数学输入语言</h3>
<p>当这些 snippets 积累到一定数量，LaTeX 输入就变成了一套个人速记语言。用户输入的不是标准 LaTeX，而是一层更短、更符合个人习惯的符号系统，然后由 snippets 翻译成 LaTeX。</p>
<p>这也是效率提升的根本原因：不是手更快，而是输入语言更短。</p>
<h2>课程专用 snippets 处理局部高频内容</h2>
<h3>不同课程有不同符号密度</h3>
<p>通用 snippets 不能覆盖所有课程。比如量子力学中 bra、ket、braket 符号出现频率极高。如果每次都手写，会非常慢。</p>
<p>作者为具体课程准备专用 snippets，通过 current_course 软链接加载当前课程的片段文件。这样同一套系统可以按课程切换。</p>
<h3>量子力学符号可以自动替换</h3>
<p>在量子力学片段中，输入 &#x3C;a| 可以生成 \bra{a}，输入 |a> 可以生成 \ket{a}，输入 &#x3C;a|b> 可以生成 \braket{a}{b}。同时，q 可以自动替换成 \psi，f 可以替换成 \phi。</p>
<p>这类设计说明 snippets 可以融入学科约定。不同课程里的常用符号不同，工具也应该跟着课程变化。</p>
<h2>上下文判断解决误触问题</h2>
<h3>自动化越多，误触风险越高</h3>
<p>如果 sr 会自动变成平方，那么普通英文单词 disregard 中的 sr 也可能触发，结果变成错误文本。snippet 越短，越容易撞上正常语言。</p>
<p>所以速度和安全之间有矛盾。触发词太长，效率下降；触发词太短，误触增加。</p>
<h3>用数学环境判断是否展开</h3>
<p>作者用 vimtex 的语法判断函数来检测当前是否处在数学环境中。只有在数学环境里，sr 这类数学 snippets 才会展开。</p>
<p>这样，普通文本中的 sr 不会被替换，公式中的 sr 可以正常变成平方。这让高频短命令真正可用。</p>
<h3>数学环境本身也有细节</h3>
<p>有些地方看似在数学环境中，但里面包了 \text{}，此时应该按普通文本处理。有些 \text{} 内部又包含数学内容，此时又应该允许数学 snippets 展开。</p>
<p>这说明上下文判断不能粗糙。真正稳定的输入系统需要理解当前位置的语法状态。</p>
<h2>拼写修正也要不中断输入流</h2>
<h3>数学笔记中大部分时间仍在写自然语言</h3>
<p>虽然数学公式重要，但笔记里也有大量英文解释。作者打字速度大约每分钟 80 词，但仍然会出现拼写错误。</p>
<p>如果每次拼错都停下来手动选择建议，输入节奏会被打断。课堂笔记最怕这种中断。</p>
<h3>Ctrl 加 L 修正上一个拼写错误</h3>
<p>作者设置了一个 Vim 快捷键，按下 Ctrl 加 L 后，自动跳到上一个拼写错误，选择第一个建议，再回到原来位置继续输入。</p>
<p>这套操作的价值在于不中断。拼写修正变成一个轻动作，不需要视线和注意力离开当前内容太久。</p>
<h2>这套方法背后的核心原则</h2>
<h3>把重复动作交给机器</h3>
<p>LaTeX 难用的部分，多数来自重复、机械、容易出错的语法输入。snippets 把这些动作交给机器，人只负责判断结构和内容。</p>
<p>这符合一个简单原则：人脑负责数学意思，编辑器负责语法包装。</p>
<h3>输入系统要顺着思考顺序设计</h3>
<p>很多 snippets 的设计都贴近手写和板书顺序。先写变量，再加修饰；先写分子，再变成分数；先输入环境名，再自动补齐结束环境。</p>
<p>工具如果强迫人按照机器语法思考，会拖慢速度。工具如果顺着人的思路补全结构，就会显著降低负担。</p>
<h3>自动化必须有边界</h3>
<p>短触发词能提速，但也容易误触。上下文判断、优先级、只在行首展开、只在数学环境展开，这些限制保证了系统稳定。</p>
<p>没有边界的自动化会变成干扰。好的自动化不是到处替你做事，而是在正确位置做正确动作。</p>
<h3>长期积累比单个插件更重要</h3>
<p>这套系统的核心不是某个神奇插件，而是长期积累下来的个人 snippets。每个片段解决一个小痛点，积累到一定数量后，就变成完整工作流。</p>
<p>这也是它最值得借鉴的地方。真正的效率工具往往不是买来就好用，而是在真实使用中一点点长出来。</p>
