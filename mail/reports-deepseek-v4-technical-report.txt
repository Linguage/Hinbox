<p>推理模型（Reasoning models）的出现确立了测试时扩展（test-time scaling）的新范式，为大型语言模型带来了巨大的性能提升。然而，这种扩展范式从根本上受限于标准注意力机制（vanilla attention mechanism）的二次计算复杂度，这为超长上下文和推理过程造成了令人望而却步的瓶颈。与此同时，从复杂的智能体工作流到大规模跨文档分析，长跨度场景和任务的出现，使得对超长上下文的高效支持对于未来的发展变得至关重要。尽管最近开源社区的努力提升了模型的通用能力，但这种处理超长序列时的核心架构低效性仍然是一个关键障碍，限制了从测试时扩展中获得进一步收益，并阻碍了对长跨度场景和任务的进一步探索。</p>
<p><img src="https://www.k-a.in/images/v4/figure1.png" alt="Figure 1"></p>
<p>右图展示了 DeepSeek-V3.2 和 DeepSeek-V4 系列估计的单 Token 推理 FLOPs 和累积 KV Cache 大小。在 100 万 Token 上下文的场景下，即使是激活参数量更大的 DeepSeek-V4-Pro，其单 Token FLOPs（以等效 FP8 FLOPs 衡量）也仅为 DeepSeek-V3.2 的 27%，KV Cache 大小仅为 10%。此外，DeepSeek-V4-Flash 将效率推向了更高的高度。在 100 万 Token 上下文设置下，与 DeepSeek-V3.2 相比，它的单 Token FLOPs 仅为 10%，KV Cache 大小仅为 7%。</p>
<p>左图展示了 DeepSeek-V4-Pro-Max 及其对应模型在基准测试中的表现。DeepSeek-V4-Pro-Max 是 DeepSeek-V4-Pro 的最大推理努力模式，它重新定义了开源模型的最先进水平，在核心任务上超越了其前代模型。在编程竞赛中，它们的表现与 GPT-5.4 相当，这也是开源模型首次在此任务上比肩闭源模型。</p>
<h2>架构变更</h2>
<p>与 DeepSeek-V3 架构相比，DeepSeek-V4 系列保留了 DeepSeekMoE 框架和多 Token 预测（MTP）策略，同时在架构和优化方面引入了几个关键创新。对于 MoE 组件，DeepSeek-V4 系列在前馈网络（FFN）中采用了 DeepSeekMoE 范式，设置了细粒度的路由专家和共享专家。与 DeepSeek-V3 相比，它们将最初几个 Transformer 块中的密集 FFN 层替换为采用**哈希路由（Hash routing）**的 MoE 层。哈希路由策略根据预定义的哈希函数，基于输入 Token ID 确定每个 Token 的目标专家。在负载均衡方面，它们也采用了无辅助损失策略（auxiliary-loss-free strategy），并辅以轻微的序列级平衡损失，以防止单个序列内部出现极端的负载不平衡。MTP 配置与 DeepSeek-V3 保持一致。</p>
<p><strong>MLA 被移除了。</strong> 为了提升长上下文的效率，他们设计了一种混合注意力机制，结合了<strong>压缩稀疏注意力 (Compressed Sparse Attention, CSA)</strong> 和<strong>重度压缩注意力 (Heavily Compressed Attention, HCA)</strong>。CSA 沿序列维度压缩 KV Cache，然后执行 DeepSeek 稀疏注意力 (DSA)；而 HCA 对 KV Cache 应用更激进的压缩，但保持密集的注意力计算。</p>
<p>他们还引入了 <a href="https://k-a.in/mHC.html">流形约束超连接 (Manifold-Constrained Hyper-Connections, mHC)</a> 来增强传统的残差连接。标准的 HC 将残差流的宽度扩展了 $n_{\text{hc}}$ 倍（在 DeepSeek-V4 中设置为 4）。HC 引入了三个线性映射：输入映射 $A_l \in \mathbb{R}^{1 \times n_{\text{hc}}}$，残差变换 $B_l \in \mathbb{R}^{n_{\text{hc}} \times n_{\text{hc}}}$，以及输出映射 $C_l \in \mathbb{R}^{n_{\text{hc}} \times 1}$。残差状态的更新公式为：</p>
<p>$$
X_{l+1} = B_l X_l + C_l \mathcal{F}_l(A_l X_l)
$$</p>
<p>mHC 的核心创新在于将残差映射矩阵 $B_l$ 约束在双随机矩阵的流形（Birkhoff 多胞形）上：</p>
<p>$$
B_l \in \mathcal{M} \coloneqq {M \in \mathbb{R}^{n \times n} \mid M\mathbf{1}_n = \mathbf{1}_n,\ \mathbf{1}_n^T M = \mathbf{1}_n^T,\ M \geq 0}
$$</p>
<p>这种约束确保了映射矩阵的谱范数 $|B_l|_2$ 的上限为 1，因此残差变换是非膨胀的（non-expansive），从而提高了前向传播和反向传播过程中的数值稳定性。集合 $\mathcal{M}$ 在乘法下是封闭的，这保证了在深度堆叠的 mHC 场景中的稳定性。输入变换 $A_l$ 和输出变换 $C_l$ 也被约束为非负，并通过 Sigmoid 函数进行有界处理，以避免信号抵消的风险。这三个线性映射的参数是动态生成的，分解为动态（依赖输入）分量和静态（不依赖输入）分量。</p>
<p>此外，他们将 Muon 优化器引入到 DeepSeek-V4 系列的训练中，带来了更快的收敛速度和更好的训练稳定性。</p>
<hr>
<p><strong>CSA</strong>，混合注意力架构的核心组件。</p>
<p><img src="https://www.k-a.in/images/v4/figure3_csa.png" alt="Figure 3, CSA Architecture"></p>
<p>CSA 的核心架构首先将每 $m$ 个 Token 的 KV Cache 压缩成一个条目，然后应用 DeepSeek 稀疏注意力进一步加速。此外，还将一小部分滑动窗口 KV 条目与选定的压缩 KV 条目相结合，以增强局部的细粒度依赖关系。</p>
<p><strong>压缩键值条目。</strong> 设 $H \in \mathbb{R}^{n \times d}$ 为输入隐藏状态的序列，其中 $n$ 是序列长度，$d$ 是隐藏层大小。CSA 首先计算两个系列的 KV 条目 $C_a, C_b \in \mathbb{R}^{n \times c}$ 及其对应的压缩权重 $Z_a, Z_b \in \mathbb{R}^{n \times c}$：</p>
<p>$$
C_a = H \cdot W_a^{KV},\quad C_b = H \cdot W_b^{KV}
$$</p>
<p>$$
Z_a = H \cdot W_a^Z,\quad Z_b = H \cdot W_b^Z
$$</p>
<p>$C_a$ 和 $C_b$ 中的每 $m$ 个 KV 条目，会根据其压缩权重和可学习的位置偏置 $B_a, B_b \in \mathbb{R}^{m \times c}$ 压缩为一个条目：</p>
<p>$$
[S^a_{mi:m(i+1)-1};\ S^b_{m(i-1):mi-1}] = \text{Softmax}<em>{\text{row}}([Z^a</em>{mi:m(i+1)-1} + B_a;\ Z^b_{m(i-1):mi-1} + B_b])
$$</p>
<p>$$
C_i^{\text{Comp}} = \sum_{j=mi}^{m(i+1)-1} S_j^a \odot C_j^a + \sum_{j=m(i-1)}^{mi-1} S_j^b \odot C_j^b
$$</p>
<p><img src="https://www.k-a.in/images/v4/csa_compression.png" alt="Equations 11-12, CSA Compression"></p>
<p>每个 $C_i^{\text{Comp}}$ 由 $2m$ 个 KV 条目推导得出，但用于 $C_i^{\text{Comp}}$ 的 $C_b$ 的索引与用于 $C_{i-1}^{\text{Comp}}$ 的 $C_a$ 的索引是重叠的。因此，CSA 实际上将序列长度压缩为原来的 $\frac{1}{m}$。</p>
<p><strong>用于稀疏选择的闪电索引器（Lightning Indexer）。</strong> 在获得压缩的 KV 条目后，CSA 应用 DSA 策略选择 top-k 的压缩 KV 条目进行核心注意力计算。CSA 执行与获取 $C^{\text{Comp}}$ 相同的压缩操作来获取压缩的索引器键（indexer keys）。然后，对于查询 Token $t$，以低秩方式生成索引器查询。查询 Token $t$ 与前一个压缩块 $s$ 之间的索引分数为：</p>
<p>$$
I_{t,s} = \sum_{h=1}^{n_h^I} w_{t,h}^I \cdot \text{ReLU}\left(q_{t,h}^I \cdot K_s^{I\text{Comp}}\right)
$$</p>
<p>给定索引分数后，top-k 选择器会选择性地保留一部分压缩的 KV 条目，用于后续的核心注意力计算。索引器在压缩条目上运行，并且闪电索引器内的注意力计算是在 FP4 精度下执行的，这极大地加速了在极长上下文下的注意力操作。</p>
<p>引入了一个滑动窗口形式（$n_{\text{win}} = 128$ 个未压缩的 KV 条目）的补充注意力分支，以更好地建模局部依赖。为了在 CSA 中严格保留因果性，每个查询只关注之前的压缩 KV 块。因此，查询无法访问其自身压缩块内其他 Token 的信息。同时，在语言建模中，最近的 Token 通常与查询 Token 具有更高的相关性。基于这些原因，滑动窗口提供了直接访问最近 Token 的途径。</p>
<p>选定的压缩条目和滑动窗口条目拼接后，被传递到共享键值 MQA（Shared Key-Value MQA）。</p>
<hr>
<p><strong>HCA</strong>，第二种注意力机制。</p>
<p><img src="https://www.k-a.in/images/v4/figure4_hca.png" alt="Figure 4, HCA Architecture"></p>
<p>HCA 的核心架构以更重度的方式压缩 KV Cache，但不采用稀疏注意力。总的来说，HCA 的压缩策略与 CSA 相似，但采用了更大的压缩率 $m'$（$\gg m$），并且不执行重叠压缩。CSA 将每 $m = 4$ 个 Token 压缩为 1 个，而 HCA 将每 $m' = 128$ 个 Token 压缩为 1 个。通过这种压缩操作，HCA 将序列长度压缩为原来的 $\frac{1}{m'}$。压缩后条目非常少，因此没有必要进行稀疏选择。HCA 保持了密集的注意力计算，并且像 CSA 一样采用了共享 KV MQA 和分组输出投影策略。</p>
<p>CSA 和 HCA 在层与层之间交替使用。对于 DeepSeek-V4-Flash，前两层使用纯滑动窗口注意力，随后的层交替使用 CSA 和 HCA。对于 DeepSeek-V4-Pro，前两层使用 HCA，随后的层交替使用 CSA 和 HCA。CSA 和 HCA 的这种混合架构显著提高了 DeepSeek-V4 系列的长上下文效率，使得在实践中处理百万 Token 上下文成为可能。</p>
<hr>
<p>CSA 和 HCA 都采用了 <strong>共享键值多查询注意力 (Shared Key-Value MQA)</strong>。</p>
<p><img src="https://www.k-a.in/images/v4/shared_kv_mqa.png" alt="Shared Key-Value MQA"></p>
<p>CSA 以多查询注意力（MQA）的方式执行核心注意力计算，其中每个压缩的 KV 条目既作为注意力键（Key），也作为注意力值（Value）。查询（Queries）是从一个压缩潜向量生成的，该向量与用于索引器查询的向量共享：</p>
<p>$$
o_{t,i} = \text{CoreAttn}\left(\text{query}=q_{t,i},\ \text{key}=C_t^{\text{SprsComp}},\ \text{value}=C_t^{\text{SprsComp}}\right)
$$</p>
<p><strong>分组输出投影 (Grouped Output Projection)。</strong> 在 DeepSeek-V4 的配置中，$cn_h$ 非常大。因此，如果直接将核心注意力操作的输出投影到 $d$ 维隐藏状态，将带来巨大的计算负担。为了减轻这种成本，设计了一种分组输出投影策略。将 $n_h$ 个输出分成 $g$ 组，对于每组，将输出投影到一个 $d_g$ 维的中间输出，其中 $d_g &#x3C; c\frac{n_h}{g}$。最后，将这些中间输出投影为最终的注意力输出。</p>
<p><strong>部分旋转位置编码 (Partial RoPE)。</strong> 对于 CSA 和 HCA，RoPE 部分应用于注意力查询、KV 条目和核心注意力输出。对于每个查询向量和 KV 条目向量，RoPE 应用于其最后 64 个维度。由于 KV 条目既用作注意力键又用作值，核心注意力的原始输出将带有绝对位置嵌入。作为应对策略，对每个输出的最后 64 个维度应用位置为 $-i$ 的 RoPE，这样核心注意力的输出就会携带相对位置嵌入。</p>
<hr>
<p><strong>QK 归一化。</strong> 对于 CSA 和 HCA，在核心注意力操作之前，都会对查询的每个头以及压缩 KV 条目的唯一一个头执行一次额外的 RMSNorm 操作。这种归一化避免了注意力 Logits 爆炸，并可能提高训练稳定性。</p>
<p><img src="https://www.k-a.in/images/v4/qk_norm.png" alt="QK Normalization"></p>
<p>DeepSeek-V4 系列的注意力架构允许直接在注意力查询和 KV 条目上应用 RMSNorm，这有效地防止了注意力 Logits 爆炸。因此，Muon 优化器中不再使用 QK-Clip 技术。</p>
<hr>
<p><strong>注意力下沉 (Attention Sink)。</strong> 在 CSA 和 HCA 的核心注意力中，采用了注意力下沉的技巧。设置了一系列可学习的下沉 Logits ${z'_1, z'<em>2, \ldots, z'</em>{n_h}}$。对于第 $h$ 个注意力头，将 $\exp(z'_h)$ 添加到注意力分数的偏母中：</p>
<p>$$
s_{h,i,j} = \frac{\exp(z_{h,i,j})}{\sum_k \exp(z_{h,i,k}) + \exp(z'_h)}
$$</p>
<p>这项技术允许每个查询头将其总注意力分数调整为不等于 1，甚至接近 0。</p>
<hr>
<p>由于采用了混合的 CSA 和 HCA，加上低精度计算和存储，注意力模块实现了惊人的效率。KV 条目采用了混合存储格式：RoPE 维度使用 BF16 精度，其余维度使用 FP8 精度。以 LLM 注意力常见的配置之一 —— 头部维度为 128 的 BF16 GQA-8 为基准，在 100 万上下文设置下，DeepSeek-V4 系列的 KV Cache 大小可大幅削减至该基准的 <strong>约 2%</strong>。</p>
<p><img src="https://www.k-a.in/images/v4/kv_cache_2percent.png" alt="KV Cache Comparison"></p>
<p>此外，即使与本身已经是一个高效基准的 DeepSeek-V3.2 相比，DeepSeek-V4 系列在效率上仍表现出巨大的优势。</p>
<hr>
<p><strong>Muon 优化器。</strong> 由于收敛速度更快且训练稳定性更好，大多数模块都使用了 Muon 优化器。论文中的算法 1：</p>
<p><img src="https://www.k-a.in/images/v4/muon_algorithm.png" alt="Algorithm 1, Muon for DeepSeek-V4"></p>
<p>AdamW 优化器仍用于嵌入模块、预测头模块、mHC 模块的静态偏置和门控因子，以及所有 RMSNorm 模块的权重。所有其他模块均使用 Muon 进行更新。对 Muon 参数应用了权重衰减，使用了 Nesterov 技巧，并且通过缩放更新矩阵的均方根（RMS）来复用 AdamW 的超参数。</p>
<p><strong>混合牛顿-舒尔茨迭代 (Hybrid Newton-Schulz Iterations)。</strong> 对于给定的矩阵 $M$，每次牛顿-舒尔茨迭代执行：</p>
<p>$$
M_k = aM_{k-1} + b(M_{k-1}M_{k-1}^T)M_{k-1} + c(M_{k-1}M_{k-1}^T)^2 M_{k-1}
$$</p>
<p>混合牛顿-舒尔茨迭代分为两个截然不同的阶段，共执行 10 次迭代。在前 8 步中，系数 $(a,b,c) = (3.4445, -4.7750, 2.0315)$ 驱动快速收敛，使奇异值接近 1。在最后的 2 步中，系数 $(a,b,c) = (2, -1.5, 0.5)$ 将奇异值精确稳定在 1。</p>
<p>随着架构中加入 QK 归一化，优化器中不再需要 QK-Clip 技术。</p>
<hr>
<p><strong>专家并行中细粒度的通信-计算重叠。</strong></p>
<p><img src="https://www.k-a.in/images/v4/ep_overlap.png" alt="Figure 5, EP Communication-Computation Overlap"></p>
<p>MoE 可以通过专家并行 (EP) 进行加速。然而，EP 需要复杂的节点间通信，对互连带宽和延迟提出了极高的要求。每个 MoE 层主要可以分解为四个阶段：两个受限于通信的阶段（Dispatch 和 Combine），以及两个受限于计算的阶段（Linear-1 和 Linear-2）。在单个 MoE 层内，通信的总时间少于计算时间。因此，在将通信和计算融合为统一的流水线后，计算仍然是主要瓶颈，这意味着系统可以在不降低端到端性能的情况下容忍较低的互连带宽。</p>
<p>专家被划分为多个波次（waves）进行调度。每个波次包含一小部分专家。只要该波次内的所有专家完成通信，计算便可立即开始，无需等待其他专家。在稳定状态下，当前波次的计算、下一波次的 Token 传输以及已完成专家的结果发送都是并发进行的。这种基于波次的调度实现了理论上 1.92 倍的加速，而 Comet 仅为 1.42 倍。该基于 CUDA 的 mega-kernel 实现（名为 MegaMoE）已作为 DeepGEMM 的一个组件开源。</p>
<p><strong>对硬件供应商的观察与建议：</strong></p>
<ul>
<li><strong>计算通信比：</strong> 完全的通信与计算重叠取决于计算通信比，而非单纯的带宽。他们鼓励未来的硬件设计瞄准这样的平衡点，而不是无条件地扩展带宽。</li>
<li><strong>功率预算：</strong> 极端的 Kernel 融合会使计算、内存和网络同时处于高负载，导致功率节流（power throttling）成为关键的性能限制因素。</li>
<li><strong>通信原语：</strong> 目前采用的是基于拉取（pull-based）的方法，每个 GPU 主动从远程 GPU 读取数据。未来具有更低延迟跨 GPU 信令的硬件，将使基于推送（push-based）的方法变得可行，并实现更自然的通信模式。</li>
<li><strong>激活函数：</strong> 他们建议将 SwiGLU 替换为一种低成本的逐元素激活函数，避免指数或除法运算。</li>
</ul>
<hr>
<p><strong>TileLang</strong>，一种用于 GPU kernel 开发的领域特定语言 (DSL)，平衡了开发效率与运行时性能。</p>
<p><strong>通过主机端代码生成 (Host Codegen) 减少调用开销。</strong> 随着加速器性能的持续增长，CPU 端的编排开销变得越来越突出。主机端代码生成将大部分主机端逻辑移入生成的代码中。每次调用的 CPU 端验证开销从几十或几百微秒骤降至不到 1 微秒。</p>
<p><strong>SMT 求解器辅助的形式化整数分析。</strong> TileLang 的 kernel 涉及复杂的张量索引算术运算，需要强大的形式化整数分析能力。Z3 SMT 求解器被集成到 TileLang 的代数系统中，为张量程序中的大多数整数表达式提供了形式化分析能力。他们将 TileLang 的整数表达式转换为 Z3 的无量词非线性整数算术 (QF_NIA)。在合理的资源限制下，Z3 提升了整体的优化性能，同时将编译时间开销限制在几秒钟内。这对多个编译 Pass 产生了实质性影响，包括向量化、屏障插入和代码简化。</p>
<p><img src="https://www.k-a.in/images/v4/smt_solver.png" alt="SMT-Solver-Assisted Formal Analysis"></p>
<hr>
<p><strong>批次不变性与确定性。</strong></p>
<p>批次不变性（Batch invariance）确保任何给定 Token 的输出保持位级（bitwise）一致，无论其在批次中的位置如何。确定性训练对于调试硬件或软件问题非常有帮助。</p>
<p><strong>注意力计算。</strong> 为了实现批次不变性，不能使用 split-KV 方法（该方法将单个序列的注意力计算分布到多个流式多处理器 (SM) 上）。然而，放弃这项技术会导致严重的波次量化问题（wave-quantization problems）。为此开发了一种<strong>双 Kernel 策略</strong>。第一个 Kernel 在单个 SM 内计算整个序列的注意力输出，确保完全占用的波次具有高吞吐量。第二个 Kernel 使用多个 SM 处理单个序列，以最小化最终未满载波次的延迟。第二个 Kernel 的计算路径经过精心设计，确保其累加顺序与第一个 Kernel 完全相同，从而保证位级一致性。第二个 Kernel 利用线程块集群内的分布式共享内存，实现了跨 SM 的高速数据交换。这种双 Kernel 方法有效地将批次不变解码的开销限制在可忽略的程度。</p>
<hr>
<p><strong>FP4 量化感知训练 (QAT)。</strong></p>
<p><img src="https://www.k-a.in/images/v4/fp4_qat.png" alt="FP4 QAT"></p>
<p>量化感知训练 (QAT) 在后训练（post-training）阶段被引入，使模型能够适应量化引入的精度下降。FP4 (MXFP4) 量化应用于两个组件：(1) MoE 专家权重，这是 GPU 显存占用的主要来源；(2) CSA 索引器中的 Query-Key (QK) 路径，其中 QK 激活完全在 FP4 中缓存、加载和乘加，从而加速长上下文场景中的注意力分数计算。</p>
<p>对于 MoE 专家权重，遵循 QAT 的常规做法，优化器维护的 FP32 主权重首先被量化为 FP4，然后反量化回 FP8 进行计算。值得注意的是，<strong>FP4 到 FP8 的反量化是无损的</strong>。这是因为 FP8 (E4M3) 相比 FP4 (E2M1) 多了 2 个指数位，提供了更大的动态范围。只要每个 FP8 量化块内各个 FP4 子块的最大和最小缩放因子之比不超过一定阈值，细粒度的缩放信息就能完全被 FP8 的扩展动态范围所吸收。他们通过经验验证了当前的权重满足这一条件。此外，索引分数进一步从 FP32 量化到 BF16，为 top-k 选择器实现了 2 倍加速，同时保留了 99.7% 的 KV 条目召回率。</p>
<p>在不涉及反向传播的推理和 RL 训练部署阶段（rollout），使用的是真正的 FP4 量化权重，而不是模拟量化。这确保了采样期间的模型行为与在线部署完全一致，同时减少了内核内存加载以实现实际加速，并显着降低了显存消耗。</p>
<hr>
<p><strong>Muon 与 ZeRO 的高效实现。</strong></p>
<p><img src="https://www.k-a.in/images/v4/muon_zero.png" alt="Efficient Muon with ZeRO"></p>
<p>Muon 优化器需要完整的梯度矩阵来计算参数更新，当与零冗余优化器 (ZeRO) 结合时，这就带来了挑战。传统的 ZeRO 是为像 AdamW 这样的逐元素优化器设计的，其中单个参数矩阵可以跨多个 Rank 进行分区和更新。</p>
<p>对于密集参数，ZeRO 并行的最大规模受到限制，采用<strong>背包算法 (knapsack algorithm)</strong> 将参数矩阵分配给这些 Rank，确保每个 Rank 管理大致平衡的负载。对于 MoE 参数，每个专家都是独立优化的。所有层的所有专家中，SwiGLU 的所有下投影矩阵（down projection matrices）首先被展平，随后是展平的上投影矩阵（up projection matrices）和门控矩阵（gate matrices）。然后，将展平的向量进行填充（pad），以确保在所有 Rank 上均匀分布，而不会拆分任何逻辑上独立的矩阵。</p>
<p>此外，在每个 Rank 上，形状相同的连续参数会被自动合并，从而实现牛顿-舒尔茨迭代的批处理执行，提高硬件利用率。Muon 中的牛顿-舒尔茨迭代在使用 BF16 矩阵乘法计算时保持稳定。利用这一点，要在数据并行 Rank 之间同步的 MoE 梯度，以随机舍入（stochastic rounding）的方式进一步量化为 BF16 精度，将通信量减半。为了避免低精度加法器引入的累积误差，传统的基于树或环的规约-散播 (reduce-scatter) 集合通信被替换为<strong>两阶段方法</strong>。首先，通过 all-to-all 操作在各个 Rank 之间交换局部梯度，然后每个 Rank 在 FP32 精度下执行局部求和。</p>
<hr>
<p><img src="https://www.k-a.in/images/v4/parallelism_kv.png" alt="Parallelism and KV Cache"></p>
<p><strong>面向长上下文注意力的上下文并行。</strong> 传统的上下文并行 (CP) 会对序列维度进行分区。训练样本由多个序列打包而成，每个序列被独立压缩 $m$（或 $m'$）倍，任何少于 $m$ 的尾随 Token 都会被丢弃。因此，压缩后的 KV 长度通常小于 $\frac{s}{m}$ 并且在各个 Rank 之间存在差异。压缩需要 $m$ 个连续的 KV 条目，这可能会跨越两个相邻 CP Rank 之间的边界。</p>
<p>为此设计了<strong>两阶段通信方法</strong>。在第一阶段，每个 Rank $i$ 将其最后 $m$ 个未压缩的 KV 条目发送到 Rank $i+1$。然后，Rank $i+1$ 将这些接收到的条目与其本地未压缩的 KV 条目一起进行压缩。在第二阶段，所有 CP Rank 之间执行 all-gather 操作，收集本地压缩的 KV 条目。最后，一个融合的 select-and-pad 算子将它们重组为完整的压缩 KV 条目集。</p>
<p><strong>KV Cache 结构与管理。</strong> 混合注意力机制引入了多种具有不同缓存大小和更新规则的 KV 条目。闪电索引器引入了与主注意力不同的额外 KV Cache 维度及嵌入大小。CSA 和 HCA 中的压缩技术将序列长度缩小为 $\frac{1}{m}$ 和 $\frac{1}{m'}$，从而减小了整体 KV Cache 大小。结果导致，不同层的 KV Cache 大小各不相同。在压缩分支中，每 $m$ 个 Token 生成一个 KV 条目。当剩余 Token 数量不足以进行压缩时，所有待处理的 Token 及其相关的隐藏状态必须保留在缓冲区中，直到可以执行压缩操作。</p>
<p>KV Cache 被组织成两个主要部分：用于 CSA/HCA 的<strong>经典 KV Cache</strong>，以及用于滑动窗口注意力 (SWA) 和尚未准备好压缩的 Token 的<strong>状态缓存 (state cache)</strong>。在状态缓存中，每个请求被分配一个固定大小的缓存块。在经典 KV Cache 中，每个请求分配多个块。每个缓存块覆盖 $\text{lcm}(m, m')$ 个原始 Token。</p>
<p>对于磁盘上的 KV Cache 存储，针对 SWA KV 条目实现了三种策略，每种策略都在存储开销和计算冗余之间提供了不同的权衡：<strong>全 SWA 缓存</strong>（存储所有 Token 的完整 SWA KV 条目），<strong>定期检查点</strong>（每隔 $p$ 个 Token 为 SWA KV 条目建立检查点），以及<strong>零 SWA 缓存</strong>（不存储任何 SWA KV 条目，而是利用缓存的 CSA 和 HCA KV 条目来重新计算最后的 $n_{\text{win}} \cdot L$ 个 Token）。</p>
<p><strong>激活重计算 (Activation Checkpointing)。</strong> 实现了一种支持自动微分的张量级激活检查点机制。开发者只需实现前向传播，并选择性地对需要自动建立检查点和重新计算的各个张量进行注释即可。该框架利用 TorchFX 跟踪完整的计算图。对于每个注释的张量，它执行反向遍历，以确定其重计算所需的最小子图。</p>
<hr>
<p><strong>预训练数据。</strong> 在 DeepSeek-V3 预训练数据的基础上，构建了更具多样性、质量更高且有效上下文更长的训练语料库。对于网络抓取数据，过滤策略删除了批量的自动生成和模板化内容，从而降低了模型崩溃 (model collapse) 的风险。数学和编程语料依然是核心组成部分。通过在中期训练阶段引入智能体（Agentic）数据，进一步提升了编程能力。对于多语言数据，构建了更大的语料库，改善了跨不同文化的针对长尾知识的捕获。特别强调了长文档数据的清洗，优先保留科学论文、技术报告及其他反映独特学术价值的材料。预训练语料库包含超过 32 万亿 (32T) 个 Token。</p>
<p><img src="https://www.k-a.in/images/v4/data_construction.png" alt="Data Construction"></p>
<p>在 Tokenization 方面，在 DeepSeek-V3 的 Tokenizer 基础上引入了少量用于上下文构建的特殊 Token，词表大小保持在 128K。</p>
<p><img src="https://www.k-a.in/images/v4/special_tokens.png" alt="Quick Instruction Special Tokens"></p>
<hr>
<p><strong>预训练设置。</strong></p>
<p><strong>DeepSeek-V4-Flash</strong>：43 层 Transformer 层，隐藏层维度 $d = 4096$。前两层使用纯滑动窗口注意力；随后的层交替使用 CSA 和 HCA。CSA 压缩率 $m = 4$，注意力 top-k = 512。HCA 压缩率 $m' = 128$。每个 MoE 层包含 1 个共享专家和 256 个路由专家，每个 Token 激活 6 个专家。在 32T Token 上进行训练。多数参数采用 Muon 优化器。AdamW 的超参数为 $\beta_1 = 0.9, \beta_2 = 0.95, \varepsilon = 10^{-20}$，权重衰减为 0.1。Muon 动量为 0.95，权重衰减为 0.1，每个更新矩阵的 RMS 缩放至 0.18。学习率经过 2000 步预热（warmup），保持在 $2.7 \times 10^{-4}$，然后按照余弦调度衰减至 $2.7 \times 10^{-5}$。训练以 4K 序列长度开始，逐渐扩展至 16K、64K 和 1M。前 1T Token 使用密集注意力，然后经历索引器预热阶段，训练剩余部分使用稀疏注意力。MTP 损失权重设置为 0.3，在学习率开始衰减时降至 0.1。</p>
<p><strong>DeepSeek-V4-Pro</strong>：61 层 Transformer 层，隐藏层维度 $d = 7168$。前两层使用 HCA；随后的层交替使用 CSA 和 HCA。CSA 压缩率 $m = 4$，注意力 top-k = 1024。HCA 压缩率 $m' = 128$。每个 MoE 层包含 1 个共享专家和 384 个路由专家，每个 Token 激活 6 个专家。在 33T Token 上进行训练。峰值学习率为 $2.0 \times 10^{-4}$，最终学习率为 $2.0 \times 10^{-5}$。与 Flash 相比，Pro 模型在密集注意力阶段的时间更长。</p>
<p><img src="https://www.k-a.in/images/v4/training_setup_pro.png" alt="DeepSeek-V4-Pro Training Setup"></p>
<p>对于无辅助损失的负载均衡，偏置更新速度设置为 0.001。平衡损失权重设置为 0.0001。MTP 损失权重在训练的大部分时间设置为 0.3，在学习率开始衰减时降至 0.1。</p>
<hr>
<p><strong>缓解训练不稳定性。</strong> 训练万亿参数的 MoE 模型面临巨大的稳定性挑战，DeepSeek-V4 系列也不例外。在训练过程中遇到过显著的不稳定挑战。虽然简单的回滚可以暂时恢复训练状态，但这并非长久之计，因为这不能阻止损失突增 (loss spikes) 的再次发生。经验表明，损失突增的出现始终与 MoE 层中的离群值（outliers）有关，而路由机制本身似乎加剧了这些离群值的出现。</p>
<p><strong>前瞻路由 (Anticipatory Routing)。</strong></p>
<p><img src="https://www.k-a.in/images/v4/anticipatory_routing.png" alt="Anticipatory Routing"></p>
<p>解耦主干网络与路由网络的同步更新显着提高了训练稳定性。在第 $t$ 步，当前网络参数 $\theta_t$ 用于特征计算，但路由索引是使用历史网络参数 $\theta_{t - \Delta t}$ 计算并应用的。在实践中，为了避免两次加载模型参数的开销，在第 $t - \Delta t$ 步就提前获取了第 $t$ 步的数据。路由索引被“前瞻性地”计算并缓存，以便稍后在第 $t$ 步使用。系统通过自动检测机制，仅在出现损失突增时才触发短暂回滚并激活“前瞻路由”；在以此模式运行一段时间后，系统恢复标准训练模式。</p>
<p><strong>SwiGLU 截断 (SwiGLU Clamping)。</strong></p>
<p><img src="https://www.k-a.in/images/v4/swiglu_clamping.png" alt="SwiGLU Clamping"></p>
<p>应用 SwiGLU 截断能有效消除离群值，且在不牺牲性能的前提下大幅提升训练过程的稳定性。在两个模型的整个训练过程中，SwiGLU 的线性部分被截断在 $[-10, 10]$ 范围内，同时门控（gate）部分的上限被限制为 10。</p>
<hr>
<p><strong>产品级细节。</strong></p>
<p><strong>工具调用 Schema。</strong> DeepSeek-V4 系列引入了一种新的工具调用（Tool-Call）Schema，使用特殊的 <code>|DSML|</code> Token，并利用基于 XML 的格式进行工具调用。XML 格式有效地减少了转义失败并降低了工具调用错误，为模型与工具的交互提供了更健壮的接口。</p>
<p><strong>交错思考 (Interleaved Thinking)。</strong> DeepSeek-V4 系列根据上下文采取不同的思考 Token 处理方式。</p>
<ul>
<li><strong>工具调用场景：</strong> 所有的推理内容在整个对话过程中被完全保留。与 DeepSeek-V3.2 在每次用户开启新一轮对话时丢弃思考轨迹不同，DeepSeek-V4 系列在所有轮次（包括跨越用户消息边界）保留完整的推理历史。这使得模型能够在长跨度的智能体任务中保持连贯、累积的思维链。</li>
<li><strong>普通对话场景：</strong> 保留原有策略。当收到新的用户消息时，前几轮的推理内容会被丢弃，这使得在持续的推理轨迹带来的好处有限的场景下，上下文能够保持简洁。</li>
</ul>
<p>对于那些通过用户消息模拟工具交互的 Agent 框架，可能无法触发工具调用的上下文路径，因此无法受益于这种增强的推理持久性。推荐在此类架构中使用非思考 (Non-think) 模型。</p>
<p><strong>快速指令 (Quick Instruction)。</strong> 在聊天机器人场景中，通常需要在生成回复之前执行一些辅助任务（例如，确定是否触发网页搜索、意图识别）。传统上，这些任务由单独的小模型处理，需要冗余的 Prefilling 过程，因为它无法复用现有的 KV Cache。现在，通过将一组专用的特殊 Token 直接附加到输入序列的末尾，每个 Token 对应一个特定的辅助任务。通过直接复用已经计算好的 KV Cache，这种机制完全避免了冗余的 Prefilling，并显著降低了用户感知到的首字延迟 (TTFT)。</p>
<hr>
<p><strong>后训练流水线。</strong></p>
<p><img src="https://www.k-a.in/images/v4/post_training.png" alt="Post-Training Pipeline"></p>
<p>虽然训练流水线在很大程度上与 DeepSeek-V3.2 相似，但他们进行了一项关键的方法论替换：<strong>混合强化学习 (RL) 阶段被完全替换为同策略蒸馏 (On-Policy Distillation, OPD)。</strong></p>
<p><strong>专家训练 (Specialist Training)。</strong> 每个模型都依次经历初始微调阶段，随后是在特定领域的 Prompt 和奖励信号引导下的强化学习 (RL)。在 RL 阶段，实现了群组相对策略优化 (GRPO) 算法。他们在不同的 RL 配置下训练出各不相同的专家模型，以促进模型针对不同推理能力的优化：</p>
<ul>
<li><strong>不思考 (Non-think)</strong>：基于习惯或简单规则进行快速、直观的响应。</li>
<li><strong>高度思考 (Think High)</strong>：有意识的逻辑分析，速度较慢但更准确。</li>
<li><strong>极限思考 (Think Max)</strong>：将推理推向极致。速度慢但非常强大。</li>
</ul>
<p>对于极限思考（Think Max）模式，会在系统提示词开头添加一条特定指令：</p>
<p><img src="https://www.k-a.in/images/v4/think_max_prompt.png" alt="Think Max Injected Instruction"></p>
<blockquote>
<p><em>"推理努力程度：必须不走捷径，达到绝对的最大化。你必须极其彻底地思考，全面分解问题以找到根本原因，针对所有可能路径、边缘情况和对抗场景进行严格的逻辑压力测试。明确写出你完整的深思熟虑过程，记录每一个中间步骤、考虑过的备选方案以及被拒绝的假设，确保绝对没有任何一个预设假设未经验证。"</em></p>
</blockquote>
<p><strong>生成式奖励模型 (Generative Reward Model, GRM)。</strong> 为了解决难以验证的任务，他们整理了以评分规则为导向的 RL 数据，并使用生成式奖励模型 (GRM) 来评估策略轨迹。RL 优化直接应用于 GRM 本身。在这种范式中，Actor 网络原生兼具 GRM 的功能，实现了模型评估（裁判）能力与标准生成能力的联合优化。通过统一这些角色，模型内部的推理能力被自然地融入其评估过程中，从而产生高度稳健的评分。由于模型利用自身逻辑推广到复杂任务，该方法仅需少量多样化的人工标注即可实现卓越性能。</p>
<p><img src="https://www.k-a.in/images/v4/grm_opd.png" alt="Generative Reward Model"></p>
<p><strong>同策略蒸馏 (On-Policy Distillation)。</strong> 在训练了多个特定领域的专家后，多教师 OPD 成为将专家能力整合到最终模型中的主要技术。给定一组 $N$ 个专家模型 ${\pi_{E_1}, \pi_{E_2}, \ldots, \pi_{E_N}}$，OPD 的目标函数为：</p>
<p>$$
\mathcal{L}<em>{\text{OPD}}(\theta) = \sum</em>{i=1}^{N} w_i \cdot D_{\text{KL}}\left(\pi_\theta | \pi_{E_i}\right)
$$</p>
<p><img src="https://www.k-a.in/images/v4/opd_objective.png" alt="OPD Objective"></p>
<p>计算反向 KL 损失需要从学生模型 $\pi_\theta$ 采样训练轨迹以维持同策略学习。通过 Logit 级别的对齐，来自物理上独立的专家权重的知识被整合到一个统一的参数空间中，这在实践中规避了传统权重合并或混合 RL 技术中经常遇到的性能下降问题。使用了十多个涵盖各个领域的教师模型来蒸馏出一个单一的学生模型。</p>
<p>采用全词表 Logit 蒸馏。在计算反向 KL 损失时保留完整的 Logit 分布，可以产生更稳定的梯度估计，并确保忠实地蒸馏教师的知识。为了提高效率，所有教师模型的权重都被卸载到集中的分布式存储中并按需加载。仅缓存教师最后一层的隐藏状态，并动态重建完整的 Logits。这种设计带来的重计算开销微乎其微，同时完全规避了显式材料化完整 Logits 的显存负担。</p>
<hr>
<p><strong>长上下文评估。</strong> DeepSeek-V4-Pro 在衡量上下文中检索能力的 MRCR 任务上超越了 Gemini-3.1-Pro，但仍落后于 Claude Opus 4.6。在 128K 上下文窗口内，检索性能保持高度稳定。虽然超过 128K 之后可以看到性能下降，但在 100 万 Token 的长度下，该模型的检索能力与闭源及开源同类模型相比依然异常强悍。在类似真实场景的 CorpusQA 上，评估结果也表明 DeepSeek-V4-Pro 优于 Gemini-3.1-Pro。</p>
<p><strong>推理评估。</strong> DeepSeek-V4-Pro-Max 在推理基准测试中超越了所有先前的开源模型，并在许多指标上媲美最先进的闭源模型。在 Codeforces 排行榜上，DeepSeek-V4-Pro-Max 目前在人类参赛者中排在第 23 位。不过，其表现略逊于 GPT-5.4 和 Gemini-3.1-Pro，表明其发展轨迹落后于最前沿模型约 3 到 6 个月。</p>
<p><strong>智能体 (Agent)。</strong> 在公开基准测试中，DeepSeek-V4-Pro-Max 与领先的开源模型（如 Kimi-K2.6 和 GLM-5.1）不相上下，但略逊于前沿的闭源模型。在内部评估中，DeepSeek-V4-Pro-Max 优于 Claude Sonnet 4.5 并接近 Opus 4.5 的水平。</p>
