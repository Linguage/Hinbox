软件工程进入代理时代

摘要

Scott Wu围绕Cognition AI、Devin和软件工程未来展开讨论。核心变化是，代码生成正在从人工敲代码转向云端代理、事件触发代理和以英文规格为源头的开发流程。软件工程的瓶颈正在从写代码，转向理解系统、处理复杂故障、组织产品需求、维护团队速度和建立高密度人才文化。

内容框架与概述

访谈开头回到Devin在2024年发布时的判断。当时全自主后台代理、自测代码、电脑操作等概念还显得超前，现在已经成为AI编程工具的共同方向。Scott Wu把下一阶段的关键放在云端代理、自动触发机制和更深的工作流接入上。代理不该只在用户手动启动后工作，它应该根据Slack消息、Linear工单、性能下降、Sentry告警、依赖升级等事件自动介入。

另一个重要方向是把英文产品规格推向开发流程的源头。现在开发者可以用英文写代码，但代码仓库仍然是最终依据，代码审查、版本控制、系统理解都围绕代码展开。未来可能变成产品规格、需求说明、行为约束和自然语言描述成为真正的源头，代码只是执行层产物。Cognition的Devin Review等产品，也在朝这个方向靠近。

后半部分转向公司组织和竞争格局。Cursor被收购后，Cognition更强调自己作为应用层公司和中立平台的价值，可以同时接入不同模型供应商。Scott Wu区分了agent lab和frontier lab，前者更重视真实用户问题、产品体验和软件产出能力。团队文化上，Cognition偏向小团队、高人才密度、强所有权和快速决策。Windsurf周末交易案例体现了这种速度，法律、工程、销售和客户沟通同时推进，目标是在极短时间内稳定产品和团队。

核心概念及解读

Software Abundance，软件丰裕

软件丰裕指软件生产的约束从工程师数量转向想象力、需求表达和组织执行力。过去一个功能能不能做，常常受限于工程人力、排期和技术债。AI代理成熟后，写代码本身会变便宜，真正稀缺的是清楚描述问题、判断什么值得做、设计可靠系统和把产品带到真实用户手里。

Cloud Agents，云端代理

云端代理是在远程环境中运行的软件工程代理。它不依赖用户本地电脑，可以持续执行任务、访问隔离环境、跑测试、处理依赖和部署相关工作。Scott Wu更看好云端路线，因为软件工程任务常常需要长时间运行、稳定环境、并行处理和企业级权限控制。

Event Driven Agents，事件驱动代理

事件驱动代理不等待人类下命令，而是由系统事件自动触发。例如API性能下降、监控告警出现、依赖库需要升级、工单被创建，代理就可以自动启动，分析问题并提交修复方案。这意味着AI编程工具会从聊天窗口变成工程系统的一部分，像值班工程师、代码审查员和运维助手一样常驻。

English as Source of Truth，英文作为事实源头

这不是简单的用英文提示词生成代码，而是让产品规格、需求说明和自然语言约束成为开发流程的权威材料。过去代码是最终事实源头，所有审查和版本控制围绕代码展开。未来可能是规格先行，代理根据规格生成、修改和验证代码，团队审查的重点也从代码细节转向意图、边界和行为结果。

Agent Lab，代理实验室

Agent Lab和Frontier Lab的目标不同。Frontier Lab追求基础模型能力和通用智能边界，Agent Lab更关注把现有和自研模型变成能在真实世界工作的产品。Cognition的定位更接近Agent Lab，研究、训练、产品和商业化都围绕一个问题展开：怎样让人们用软件创造更多东西。

访谈要点

软件工程的未来已经提前到来

Devin发布时的判断正在兑现

两年前Devin发布时，完整的自主后台代理、自测代码、电脑操作能力还显得超前。现在这些方向已经进入软件工程工具的主流讨论。代码生成工具不再只是补全几行代码，而是开始承担完整任务，从理解需求、修改代码、运行测试，到在后台持续工作。

这里的关键变化是，工程师和AI之间的关系变了。过去人写代码，工具提供辅助。现在越来越多场景里，人提出目标，代理负责执行。人类的工作重心开始从敲代码，转向定义问题、验收结果、判断方向。

手写代码的重要性下降

Scott Wu提到，现在多数人已经不该继续把大量时间花在手动输入代码上。这个判断很激进，但不是说工程能力消失，而是说工程能力的表达方式变了。懂系统、懂产品、懂调试、懂验证的人，仍然重要；只会把需求翻译成代码的人，会越来越难保持优势。

未来的软件工程师更像系统导演。你要知道哪里出了问题，知道怎样拆任务，知道怎样验证结果，知道什么时候让代理继续跑，什么时候应该打断它。

本地代理与云端代理的分歧

代理会越来越向云端移动

当前AI编程工具的一条分界线，是本地代理和远程代理。前者运行在用户自己的电脑上，后者运行在云端虚拟机或隔离环境里。Cognition更看好云端方向，因为真正复杂的软件工程任务往往需要长时间运行、完整环境、权限管理、测试执行和并行任务处理。

本地代理适合轻量任务，比如编辑文件、解释代码、做小范围修改。云端代理更适合接管完整工程任务，比如修复复杂Bug、跑测试、部署到特定环境、处理企业客户的私有云需求。

云端代理更接近真正的工程同事

一个成熟的远程代理不只是聊天框里的代码助手。它可以有自己的工作环境，可以拉代码、跑命令、查日志、读文档、提交PR。它的价值不在于写出某段代码，而在于能否完整地走完软件工程生命周期。

这也是Devin这类产品的定位。它不是IDE插件，而是一个远程工程代理。它越接近完整工程师，越需要处理工程现场里的脏活：环境配置、依赖冲突、权限问题、测试失败、客户约束、历史代码风格。

事件驱动代理会成为下一阶段重点

代理不应等待人类手动启动

现在很多AI工具还需要人主动发起任务。比如收到Slack消息、Linear工单、Sentry报警后，工程师手动告诉代理去处理。Scott Wu给出的方向是，代理应该在事件发生时自动启动。

比如某个API接口比一周前慢了，系统应该自动拉起代理检查原因。依赖库需要升级，代理可以定期扫描并处理。PagerDuty或Sentry出现告警时，代理可以成为第一响应者，先做初步定位、复现和修复建议。

软件工程会从响应式变成常驻式

传统工程流程里，人类发现问题，然后组织修复。事件驱动代理出现后，工程系统会逐渐变成常驻巡检。代理可以持续观察代码库、性能、依赖、安全告警和用户反馈。

这会改变工程团队的工作节奏。很多小问题不再进入人工排队系统，而是在早期就被代理处理。工程师更多处理高判断任务，比如架构决策、风险评估、产品取舍和重大故障。

英文规格会逐渐成为事实源头

代码不再是唯一权威材料

现在虽然可以用英文写代码，但代码仓库仍然是事实源头。审查代码时看代码，版本控制提交代码，理解系统也从代码开始。Scott Wu的判断是，未来很多事情会转向英文，也就是产品规格、需求文档、行为描述和约束规则。

这不只是提示词工程。真正的变化是，团队以后可能先维护产品规格，再由代理让代码与规格保持一致。代码会变成规格的实现结果，而不是团队理解产品的唯一入口。

DeepWiki和产品规格可能变成操作界面

Q&A里提到DeepWiki这类界面。当前它更像从代码库中生成出来的解释文档，帮助人理解系统。未来它可能进一步变成修改入口。你不再直接改代码，而是在规格文档里写：增加一个新套餐，余额为零时怎样处理，用户权限怎样变化。代理再把这些变化反映到产品里。

这一步还需要模型能力和产品UX继续发展，但方向很明确：人类通过自然语言维护意图，代理负责把意图落到系统中。

写代码已接近成熟，真正难题在代码生命周期

单文件代码生成已经相对可靠

Scott Wu把当前模型能力讲得很直接：如果要求模型生成一个单文件，实现明确功能，大多数模型已经能做到不错。也就是说，AI编程最早解决的是写代码这个局部环节。

但真实软件工程远比写一个文件复杂。真正难的是理解已有代码库，定位复杂Bug，遵守团队风格，向人类解释变更，把结果放到审查流程里，并保证系统行为符合预期。

软件工程的低垂果实还很多

接下来提升空间不在于让模型多写几行代码，而在于让模型更适应工程现场。比如：它能否读懂十年历史的代码库，能否知道哪些测试该跑，能否区分临时修补和长期方案，能否把上下文用人类能理解的方式汇报出来。

这也是为什么应用层公司仍有价值。基础模型很强，但基础模型不一定天然适合工程流程。产品、上下文、权限、环境、评审、客户部署，这些才是代理真正落地的地方。

Agent Lab与Frontier Lab的区别

Frontier Lab追求基础智能

Frontier Lab的核心目标是推进模型边界，追求更基础、更通用的智能能力。它们会做大规模模型训练，研究推理、知识、规划、多模态和通用能力。

这种组织的第一目标偏研究。产品、收入和应用当然重要，但根本牵引力来自模型能力本身。

Agent Lab追求现实世界中的软件生产

Cognition更像Agent Lab。它也做模型训练和研究，但研究项目服务于一个具体目标：让人们用软件生产更多东西。换句话说，模型能力只有进入真实工程流程，才算完成一半。

这里的判断很应用层。Cognition关心的是Devin体验是否变好，客户是否更快拿到价值，产品规格能否成为新的开发入口，代理是否能处理真实企业环境里的复杂任务。

应用层和中立平台的价值

Cursor被收购后，中立性变得更稀缺

访谈中谈到Cursor被收购。Scott Wu对这件事的反应很耐人寻味：对Cognition来说，这是利好。因为如果一个重要AI编程工具被模型或算力巨头吸收，市场会更重视仍然保持独立的应用层公司。

Cognition强调自己是中立方，可以与不同模型供应商合作。这种位置类似瑞士：不被单一模型生态绑定，而是根据产品体验和客户需求选择最合适的模型与基础设施。

应用层不是简单套壳

AI应用层的价值不在于把模型包装一下，而在于把模型变成完整工作系统。软件工程代理需要客户环境、工程流程、权限系统、团队规范、部署方式和商业场景。谁能把这些环节做好，谁就拥有应用层壁垒。

这也是Cognition强调产品体验和客户价值的原因。代码生成只是入口，真正的竞争在于端到端的软件生产能力。

人才密度与小团队扩张

前50人中大量成员有创业经历

Cognition早期团队里，超过一半的人有创业经历。原因不只是这些人聪明，更因为他们习惯从第一性原理出发，愿意承担完整责任，能够在不等层层指令的情况下推进事情。

这种人才适合低管理层级的组织。公司不希望人只是完成一个小模块，而是希望每个人像所有者一样行动，看到问题就处理，看到机会就推进。

高标准比盲目扩张更重要

Scott Wu承认公司可能应该更大，但他强调高标准的价值经常被低估。小团队在高速增长时，如果每个关键位置都足够强，沟通成本会低很多，推进速度也会快很多。

Goldman Sachs企业客户案例很典型。通常大型企业采购软件可能需要12到18个月，Cognition用约3个月完成。背后不是单点销售能力，而是工程、基础设施、私有云部署、用户教育、产品适配和客户沟通一起推进。

公司文化的核心：正确优先于舒适

官僚化往往不是故意发生的

访谈里对大公司官僚化的解释很值得注意。很多人并不是想让组织变慢，也不是故意制造流程。但随着组织扩大，每个人都有自己的激励，比如个人声誉、晋升、部门利益，信息经过多层传递后，原本重要的内容会被扭曲。

官僚化的可怕之处就在这里。它不是某个人作恶，而是很多合理的小动作叠在一起，让组织慢慢失去判断力。

鼓励直接分歧

Cognition鼓励人们直接表达不同意见。只要某种做法更有利于成功，即使它不自然、不舒服、不符合常规组织方式，也应该推进。

这套文化的代价是摩擦会变多。人会被迫面对尴尬的判断、难处理的人事安排、不舒服的决策。但对早期公司来说，舒适感经常会吞掉速度和正确性。

Windsurf周末交易体现了速度逻辑

机会窗口只有一个周末

Windsurf原本涉及OpenAI和Google相关交易，后来留下了产品、客户、IP、市场团队和运营体系。Cognition意识到这里有机会，但窗口非常短。如果拖一周，客户会质疑产品是否还能继续用，团队成员会被硅谷其他公司迅速挖走。

所以他们从周五下午开始行动，周五晚上冷邮件和Zoom沟通，周六线下见面并签署意向书，周日推动律师完成交易。目标是在周一早上前稳定局面。

速度来自多线并行

这件事不是只有CEO和律师在谈。法律团队在推进交易，工程团队在研究怎样保持服务运行，怎样重新接入Anthropic，市场团队在准备客户沟通和公告。每条线都在同时推进。

这里的组织能力很关键。很多公司也会说速度重要，但真正速度来自信任、权限、判断力和激励对齐。律师按小时收费，天然不急；Cognition用奖金把目标对齐，让法律流程从几周压缩到当天。

外界对Cognition工作文化的误解

高强度不等于被动压榨

外界容易把Cognition描述成靠过度工作推动公司。Scott Wu的回应是，他们确实工作强度高，但没人拿着表检查工时。很多人愿意工作到很晚，是因为他们觉得这件事有意思：教AI写代码、服务客户、让业务增长。

这不代表所有公司都能复制这套模式。它依赖人群选择、任务吸引力、团队密度和公司阶段。对一群想学会创业、想承担大责任的人来说，高强度可能带来快速成长。对普通组织来说，照搬只会变成加班文化。

最好的学习发生在极端事件里

Windsurf周末被描述成一次压缩版公司建设训练。一个周末里要处理交易、工程、客户、团队、沟通和外部舆论。这样的经历可能比几个月常规工作学到更多。

这也是创业公司吸引前创始人的原因。它给人的不是单一技能训练，而是完整业务系统的现场经验。

后AGI时代的工作观

长期看，工作本身可能被重新定义

当被问到后AGI世界中哪些技能还重要时，Scott Wu的回答很直接：长期看，人类可能会超越对工作的依赖。他把今天的知识工作和古代农耕劳动做对比。古人看到现代人坐在电脑前按按钮、开会，可能也会疑惑这怎么能算工作。

这个类比说明，工作不是固定概念。技术改变生产方式，也会改变人对工作的理解。未来如果基础生活资料不再依赖人类经济产出，职业焦虑本身也会换一种形态。

中间阶段仍然会有剧烈重组

长期愿景很远，中间阶段会更混乱。工程师、产品经理、研究员不会立刻失去价值，但他们的价值衡量方式会改变。懂得把AI变成生产系统的人会受益，只停留在传统技能边界里的人会承压。

所以更现实的问题不是保住某个职业名称，而是掌握问题定义、系统判断、验证能力、组织协作和产品敏感度。

代理技能与知识沉淀

Skills本质上是组织经验的封装

Q&A里提到agentic skills。Cognition内部早期称之为knowledge，后来逐渐演化成不同形态。很多skills来自代码库实践，比如如何运行测试，如何遵守内部规范，如何处理特定工程流程。

这说明代理的能力不只来自模型。一个代理要在公司内部有用，需要吸收组织的工程经验。模型是大脑，skills像操作手册和肌肉记忆。

远程代理更需要上下文积累

本地代理能做轻量编辑，远程代理要做完整任务。任务越完整，越需要知道公司的习惯、工具链、测试方式、部署流程和历史约束。没有这些上下文，代理就会像新员工一样频繁踩坑。

所以未来AI工程产品的竞争，可能会转向谁能更好地沉淀组织知识，并让代理持续使用这些知识。

软件丰裕时代的真实含义

约束从工程师数量转向想象力和判断力

视频标题里的Software Abundance，核心是软件会变得更便宜、更容易生产。过去很多公司缺工程师，很多需求排不上期。AI代理成熟后，软件生产能力会显著增加，工程师数量不再是唯一瓶颈。

新的瓶颈会变成：你是否知道要做什么，是否能描述清楚，是否能判断结果好坏，是否能组织系统不断迭代。想象力变重要，但不是空想式想象力，而是能落地为规格、流程和产品判断的想象力。

软件吞噬世界之后，AI开始吞噬软件

过去常说软件正在吞噬世界。现在进入下一步：AI正在吞噬软件生产过程。软件仍然重要，但生产软件的方式正在变化。AI代理越成熟，软件行业的权力结构也会变化。

模型公司、应用层公司、云基础设施、企业客户、工程团队都会重新分工。Cognition押注的是应用层和代理层：把AI放进真实工程现场，让软件生产速度和规模发生变化。
